# Scope & Change Discipline

- **Minimal diffs:** Fix only what the task requires. No drive-by refactors, dependency upgrades, or unrelated folder changes.
- **One concern per PR/commit:** e.g. “add ProductCard component”, not “add ProductCard + reformat entire repo”.
- **No over-engineering:** No abstractions for one-off use, no premature auth/payment integrations, no test suites for trivial glue code unless requested.
- **Match existing conventions** in the file and folder you are editing.
